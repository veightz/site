技术知识往往不是「读完一段定义就懂」。读者需要看到关系、过程、约束，有时还要亲手改参数，才敢说自己理解了因果。问题是：什么时候用精炼文字就够，什么时候值得做动画、Scrollytelling（滚动叙事）或 Interactive Lab（交互实验）？

本文给出一套选型原则和一个可复用的教学设计模板。核心立场很简单：**交互不是目的，理解才是目标。**

## 不同媒介擅长什么

| 媒介 | 更适合 | 常见误用 |
| --- | --- | --- |
| 精炼文字 + 表格 | 定义、边界、争议与来源 | 用大段散文重复本可用表格说清的对比 |
| Mermaid / SVG | 架构、依赖、状态转换 | 用多段文字反复描述同一条路径 |
| 分步动画 / Scrollytelling | 时间演化、多步骤揭示、空间变化 | 把每一帧都截成静态图堆砌 |
| Interactive Lab | 参数影响、竞争、反馈循环 | 只展示一个固定结论，却假装「可探索」 |
| Slide / Document + 练习 | 系统化学习路径 | 简单拼接博客全文当教材 |

一句话对照：

- **文字**适合抽象定义和精确论证。
- **图表**适合关系与比较。
- **动画**适合时间过程。
- **参数实验**适合系统行为与因果探索。

## 三种可参考的风格

### Explorable Explanations（可探索式解释）

先让读者接触具体问题或体验，再逐层解释抽象规律，最后开放 Sandbox，让其自行探索新问题。Nicky Case 的 [The Evolution of Trust](https://ncase.me/trust/) 与 [LOOPY](https://ncase.me/loopy/) 是常见范例；他关于制作方法与设计模式的笔记也很值得对照阅读。

### Distill 风格

把可视化、数学、实验和论证整合进一篇严谨的技术文章——图表本身参与解释，而不是页边装饰。[Distill](https://distill.pub/) 以及像 Feature Visualization 这类文章，展示的是「图在论证链里干活」。

### Scrollytelling（滚动叙事）

用滚动位置驱动持续存在的图解状态，适合多步骤、时空变化与渐进揭示。[The Pudding](https://pudding.cool/) 是代表性做法。窄屏、触控滚动和无障碍模式下，需要准备回退（例如可跳过的分步说明），不能默认桌面滚轮体验处处成立。

## Blog / Slide / Document / Lab 不互相替代

同一份知识可以复用同一个 Widget，但：

- **文章**要有自己的论证结构；
- **课程**要有自己的教学顺序；
- **实验页**要有自己的初始状态、边界与重置。

把博客全文粘进幻灯片，或把实验截图塞进正文当结论，通常两边都会变差。

## 一个可复用的教学设计模板

1. **Question（问题）**：提出能引发好奇的具体问题。
2. **Experience（体验）**：先给可观察的初始实验，而不是先堆理论。
3. **Explanation（解释）**：用逐步揭示的模型解释现象和关键约束。
4. **Exploration（探索）**：开放参数，让读者构造反例、改变条件。
5. **Reflection（验证理解）**：预测结果、解释失败模式或做练习——不要把交互次数当成学习成效。

例子：「增加 Worker 是否一定能提升吞吐量？」可以调节 Worker 数、CPU 配额、锁竞争，观察何时吞吐量反而下降。**模型必须标注简化假设，不得冒充真实 Runtime Benchmark。**

## 实施与质量标准

- 从一个知识点生成**最小可验证 Widget**；先保证解释准确、可复现，再追求复杂动效。
- Widget 应明确参数、初始状态、边界条件、重置方式、无障碍交互，以及对移动设备的适配。
- 同一概念优先复用一个组件；不同视图只换讲解与引导，不复制多套实现。
- 评估效果时，除停留时间与点击外，可用「阅读前后的预测 / 解释题」做对照。
- AI 可以建议合适的表达形式，但模型假设、事实来源和交互反馈的正确性必须人工核验。

## 和「渐进式沉淀」的关系

收件箱阶段默认精炼 Markdown，把目标、原理、引用和源码链接记清楚即可；交互模拟器属于博客或教材等正式 View 的资产。先有可独立阅读的结论，再决定要不要为某个概念做实验——这样维护成本更可控。

## 待验证

1. 对同一复杂概念分别提供文字图解与交互实验，比较理解度、制作成本与维护成本。
2. 验证 Scrollytelling 在窄屏、触控滚动、无障碍模式下的回退方案。
3. 梳理第一批可复用的教材组件类型；暂不建设全自动「知识转动画」平台。
